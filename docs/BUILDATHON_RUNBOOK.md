# Four-hour buildathon

Before the event, verify the baseline using the deployment checklist, then tag the commit as `starter-baseline`. Warm the existing Render service before the demo if it has been idle.

| Time | Developer | Research | UI/UX and QA |
| --- | --- | --- | --- |
| 0–25 min | Confirm the smallest demo flow and write the first migration | Extract requirements and rank gaps | Sketch the primary screens and happy path |
| 25–110 min | Build the main API and screen flow | Resolve domain rules and supply sample inputs | Define loading, invalid-input, and empty states |
| 110–175 min | Finish the end-to-end flow and deploy | Validate results against the problem statement | Test auth, the main workflow, and mobile layout |
| 175–220 min | Fix demo blockers and verify on Render | Prepare the demo narrative | Run the QA checklist on the deployed URL |
| 220–240 min | Rehearse and save the known-good commit | Time the presentation | Verify the deployed flow and demo account |

Start your coding agent with the problem statement and `AGENTS.md`. Ask it to implement the smallest end-to-end workflow using the starter modules, then add domain rules and screens. Keep the main branch deployable.
